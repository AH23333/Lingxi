## 一、H3：LLM 生成在途时退出 LingxiUI（退出时序竞态）

- **审计条目**：H3（审计报告 §一-H3、§7.2、§7.5）。**2026-11-03 复核：H3 已根治闭环（`b8d1d8d` main 域停机不析构+落盘线程去 this 化），§八-1/-2 销账、残余转 §八-6/-7；重排/续写在飞时的真实停机路径已由台架工装 B 实测 3/3 干净退出（退出码 0、无 WER dump）。本剧本降为可选终检**——覆盖台架构不出部分：真实 TIP 宿主、托盘退出入口、可见候选窗行为。
- **目的**：证明"正在重排/续写生成时退出程序"不再闪崩（旧缺陷：退出时后台线程还在碰已释放对象）。
- **前置**：通用前置 1/2/3；模型已加载过（先正常打一段字让候选窗出过 LLM 重排结果，避免首轮冷加载干扰）。

**操作步骤**（每轮 ≈1 分钟，共 10 轮）：

1. 在记事本里用灵犀输入一段较长拼音（如 `wojintianxiangqubeijingchail`），**在候选窗刚弹出/续写候选还在陆续出现时**（生成中，约 1~2 秒窗口内），立即右键托盘图标 →"退出"。
2. 观察退出过程：托盘图标消失、进程结束，**期间不应出现任何"灵犀输入法已停止工作"弹窗**。
3. 随便再打几个字——LingxiUI 会被宿主自动重新拉起（**这是正常行为，不是 bug**），等托盘图标回来后做下一轮。
4. 重复 1~3 共 10 轮。每轮在第 1 步尽量卡在"生成刚出到一半"的时刻；另外补 2 轮变体：(a) 打字打到一半（组合串还在）直接退出；(b) 开机自启后立刻退出。

## 二、L4 + M3：宿主卸载 DLL（切输入法/关宿主/UI 卡顿叠加）

- **审计条目**：L4（DllCanUnloadNow 判定）+ M3（pipeclient::Stop 超时路径）。两者同根：宿主卸载 IME DLL 时线程未收敛 → 宿主崩溃。**2026-11-03 起本剧本同时是 §八-6（pipeclient DLL 侧窄窗口 UAF——有意维持现状）的唯一真机验证口。**
- **目的**：证明 DLL 被宿主卸载的各个时机（切 IME、关宿主、移除 TIP），即使 UI 侧卡住，**宿主进程也不崩**。
- **前置**：通用前置 1/2/3；可选装 Sysinternals `pssuspend.exe`（做 2c 用）。

**操作步骤**：

1. **2a 常规切换/关闭（每宿主各做 5 轮）**：在记事本、VS Code、Word 里分别：用灵犀打几个字 → Win+Space 切到别的输入法 → 再切回来 → 关闭该宿主窗口。全程宿主不应闪退。
2. **2b 生成在途时切走/关闭**：在宿主里输入触发 LLM 重排/续写（同剧本一第 1 步时机），**生成未完成时**立刻 Win+Space 切走输入法，或直接关闭宿主窗口。重复 5 次。
3. **2c UI 卡顿叠加（关键场景，做 3 轮）**：
   1. `pssuspend LingxiUI`（挂起 UI 进程，模拟 UI 无响应；窗口会冻住，正常）。
   2. 在宿主里切走输入法、再关闭宿主窗口。
   3. `pssuspend -r LingxiUI`（恢复）。
   4. 观察：宿主关闭过程是否弹"已停止工作"。
4. **2d 停用 TIP（收尾做一次）**：设置 → 时间和语言 → 语言和区域 → 中文(简体，中国) → 键盘 → 移除"灵犀输入法"；或管理员跑 `tools\unregister.cmd` 后注销再登录。期间保持 2~3 个宿主开着并打字。注销/登录与移除过程不应产生宿主崩溃。

**预期结果**：

- ✅ 正常（通过）：以上全部操作后，记事本/VS Code/Word 均无崩溃弹窗；事件查看器无"故障模块 = ImeCore.dll"的 Application Error；移除 TIP 后其他输入法工作正常。
- ❌ 异常（复现）：任何一次宿主闪退/挂起后崩溃，尤其故障模块指向 ImeCore.dll；或 2c 恢复 UI 后打字候选彻底不出现且重启 UI 也无效（记录现象即可，可能是卸载判定过保守，属可接受，但要报）。

## 三、M4：候选窗显示时焦点切走

- **审计条目**：M4（失焦只隐窗不清候选，DLL 仍认领选词键）。
- **目的**：证明失焦后候选窗**真的清干净**——不残留、数字/字母键不再被吞。
- **前置**：两个可并排的窗口（如记事本 + VS Code），灵犀为当前输入法。

**操作步骤**（共 10 轮，两种切法各 5 次）：

1. 在记事本输入拼音到**候选窗已弹出**（如 `zhongguo` 不打空格，让候选窗挂着）。
2. 切走焦点：(a) 组用 Alt+Tab 切到 VS Code；(b) 组用鼠标点击 VS Code 窗口。
3. 立即检查两点：① 候选窗是否已从屏幕上消失（含"半透明残影/幽灵窗"）；② 在 VS Code 里直接敲 `12345abcde`，**每个字符都必须原样上屏**。
4. 切回记事本再打一次拼音，确认组合/候选功能正常（无"上次残留状态"干扰，比如首键直接变成选词）。

**预期结果**：

- ✅ 正常（通过）：10 轮全部——焦点切走候选窗即消失；新窗口击键 0 吞键；切回后打字正常。
- ❌ 异常（复现）：候选窗残留/闪烁不消失；或新窗口里数字/字母有被吞、输出错位（如敲 `1` 出了别的候选词）；或切回后第一次组合行为异常。

## 四、L6：备份导出失败路径 + 还原后的 500ms 陈旧窗口

- **审计条目**：L6（reg.exe 超时/失败处理，§八-4 待真机）。
- **目的**：证明 ① 导出失败时提示准确、不留孤儿 reg.exe；② 导入还原后设置能在 1 秒内生效（M5 缓存的 500ms TTL 兜底真的兜得住）。
- **前置**：通用前置 1/4（本剧本需要 LINGXI_LOG=1）。

**操作步骤**：

1. **4a 失败路径**：
   1. 建一个只读目录：管理员 PowerShell 跑 `mkdir D:\lx-ro; icacls D:\lx-ro /deny "*SID yourself:(OI)(CI)W"`——嫌麻烦就换一个实际不可写的目标（如插着写保护开关的 U 盘）。
   2. 托盘右键 →"导出设置备份…"→ 存到该目录。
   3. 检查弹窗文案：**必须明确报失败**（"导出失败（路径不可写或 reg.exe 不可用）"），不得报"已导出"。
   4. 跑 `Get-Process reg -ErrorAction SilentlyContinue`：**不得有残留的 reg.exe 进程**。
2. **4b 正常路径**：导出到桌面成功；目标处应看到 `LingxiIme-设置备份-YYYYMMDD.reg` 及 `-用户词典.txt`/`-热键短语.txt`/`-屏蔽词.txt` 随行文件（有数据才生成随行）。
3. **4c 还原陈旧窗口（核心）**：
   1. 确认当前"拼音组合模式"为**开**（托盘菜单该项有勾选；打字 `nihao` 出组合）。
   2. 若 4b 的备份是在开状态下导出的就用它；不是就现在重新导出一次。
   3. 托盘 →"拼音组合模式"→ 关掉（打字变直通）。
   4. 托盘 →"导入设置备份…"→ 选备份 → 确认覆盖；随行文件询问时**词典/短语/屏蔽词都选取消**（本剧本不测数据恢复）。
   5. 导入完成提示出现后**立刻**打字：允许这一次还是直通（≤500ms 旧缓存，属设计内）。
   6. 等 1 秒再打字：**必须恢复组合模式**。
4. **4d（可选，能构造才做）超时路径**：把备份目标设到明显很慢的位置（网络盘/老 U 盘），若真触发 15 秒超时，应弹"导出失败：reg.exe 超时已强制结束…"，且 `Get-Process reg` 无残留。构造不出来就记 UNTESTED，不强求。

**预期结果**：

- ✅ 正常（通过）：4a 报失败且无孤儿；4b 文件齐全；4c 第 6 步 1 秒内恢复组合；4d（若做）提示"超时已强制结束"且无孤儿。

## 五、L7：刚学的词立刻导出（在途数据收敛）

- **审计条目**：L7（导出前未 flush 在途学习，§八-4 待真机）。
- **目的**：证明"刚学会还没落盘的词"在导出时会被强制收敛进备份文件。
- **前置**：LINGXI_LOG=1 已开；记下 `%APPDATA%\LingxiIme\userdict.txt` 当前行数：`(Get-Content "$env:APPDATA\LingxiIme\userdict.txt" -EA SilentlyContinue).Count`。

**操作步骤**（共 3 轮）：

1. 挑 3 个你**从没打过**的冷门词（每轮换一组，例如"鸽笼""熵增""钨钢"），在记事本里逐个打全拼并**从候选窗点选该词上屏**（选词即学习；一轮内只学这 3 个，不足 5 个词，确保还压在批量落盘周期里）。
2. 学完最后一个词后 **10 秒内**：托盘 →"导出设置备份…"→ 存到桌面。
3. 打开同名的 `<备份名>-用户词典.txt`，逐个搜本轮 3 个词：`Select-String -Path .\xxx-用户词典.txt -Pattern '鸽笼|熵增|钨钢'`。

**预期结果**：

- ✅ 正常（通过）：3 轮里，刚学的词**全部**出现在导出文件中。
- ❌ 异常（复现）：任何一个刚学（<10 秒）的词缺失，但过几分钟再导出又出现 → 即收敛钩子失效，记录缺失词与时刻。

## 六、L8：管理窗删除（外部改文件后的越界删除）

- **审计条目**：L8（越界删除曾假报"已删除"，§八-4 待真机）。
- **目的**：证明列表与文件脱节时，删除操作给出**明确提示**而不是虚假成功。
- **前置**：三个窗口的入口——自定义短语：设置页(左键托盘)→"词典"标签→自定义短语"管理短语"；快捷短语：同标签→快捷短语"管理短语"；屏蔽词：托盘右键→"屏蔽词管理…"。对应文件：`phrases.txt` / `hotphrases.txt` / `blocked.txt`。

**操作步骤**（每个窗口 1 轮）：

1. 打开窗口；列表若不足 2 条，先加 2 条并保存（让列表"有货"）。
2. **保持窗口开着**，用记事本打开对应 txt 文件，**删掉其中一行**（挑列表里靠后的一条），保存关闭。
3. 回到管理窗，在（旧）列表里选中刚被外部删掉的那条 → 点"删除选中"（或按 Delete 键）。
4. 检查提示语与文件：
   - 应提示**列表已变化/请刷新后重选**这类明确信息；
   - 不得提示"已删除"这种虚假成功；

## 十、如何取证据（统一说明）

1. **事件查看器**（崩溃首选入口）：`eventvwr.msc` → Windows 日志 → 应用程序。筛"错误"级，两类关键条目：
   - 来源 **Application Error**（事件 ID 1000）：里面直接写明故障模块（`LingxiUI.exe` 还是 `ImeCore.dll` 还是宿主）——截图整条详细信息即可。
   - 来源 **Windows Error Reporting**（事件 ID 1001）：含故障桶（bucket）。
2. **崩溃转储**：
   - LingxiUI：跑过一次 `tools\setup_dumps.cmd`（管理员）后，崩溃自动落 `%TEMP%\lingxi-dumps\LingxiUI.exe_*.dmp`（全量，留 5 份）。
   - 宿主崩溃（Word/Code/notepad++）：同一机制换个进程名，管理员跑（以 Notepad++ 为例）：
     `reg add "HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\notepad++.exe" /v DumpFolder /t REG_EXPAND_SZ /d "%TEMP%\lingxi-dumps" /f` 与 `/v DumpType /t REG_DWORD /d 2 /f`。
   - 手动抓活体快照（不崩溃但行为异常时用，Sysinternals ProcDump）：
     `procdump -accepteula -ma LingxiUI.exe D:\dumps\ui.dmp`；守崩溃：`procdump -accepteula -e -ma LingxiUI.exe D:\dumps\`。
3. **文件日志**：`%TEMP%\lingxi-ime.log`（需 `setx LINGXI_LOG 1` + 重新登录；每行带 `时:分:秒.毫秒 [PID] [标签]`；超 1MB 自动轮转成 `.log.old`，复现时两份都留着）。抓法：复现后立刻
   `Copy-Item "$env:TEMP\lingxi-ime.log" D:\dumps\`，并记下现象发生的时刻，我按时间戳对行。
4. **最小复现记录模板**（每条 FAIL 都按这个给）：`剧本号 + 日期时间(到秒) + 逐步操作序列 + 现象截图 + dmp/日志路径 + 当时 LINGXI_LOG 开/关`。
5. **孤儿进程检查**：`Get-Process reg,cmd,LingxiUI -ErrorAction SilentlyContinue | Format-Table Id,ProcessName,StartTime`。
