## 2. 目标行为

**一句话体验**：用户在"词库管理"窗里安装一个领域词包（如"编程术语.lxcell"），勾选启用后，打对应拼音时该包词条出现在候选里；取消勾选立即消失；多个包并存互不影响；卸载包不碰用户自学习数据。

**明确不做**（第一期）：
- 不做云词库/在线下载/词库市场（离线基线）。
- 不做每包权重滑杆（搜狗有权重调节；第一期只做"启用/停用"二值，权重进格式字段但不做 UI）。
- 不做搜狗 .scel 的**运行时原生加载**（见 §3.4：只做可选离线转换工具，不进产品主链路）。
- 不做细胞词条的逐词编辑/删除（右键"删除该词"仍只作用用户词典）。

## 3. 数据模型与文件格式

### 3.1 包文件格式 `.lxcell`（自定义纯文本，第一期唯一原生格式）

```
LXCELL 1                      ; 魔数+格式版本（缺省=1，读侧只认 1）
name=编程术语                  ; 显示名（必填）
id=prog-terms                 ; 稳定标识（必填，小写字母数字-，启用表/去重用）
weight=2                      ; 可选，0..9，缺省 2（第一期不参与排序，仅存储）
; ---- 词条区，每行一条 ----
词\t音节1 音节2 [\t权重]       ; 与 zh_pinyin.txt 同构，向后兼容可互转
```

- 编码 UTF-8（允许 BOM，读侧 `p[0]==0xEF` 跳过，先例 L1164）；CRLF/LF 均可。
- 词条行与基础词库 `Load()` 解析复用同一函数（L672-L691 的列切分逻辑抽出），音节合法性校验复用音节表。

### 3.2 存储位置与启用状态

- 包文件：`%APPDATA%\LingxiIme\cell\<id>.lxcell`（与 userdict.txt 同根，**不进 exe\data**，避开升级覆盖与 ProgramData 权限坑，基线 §四-4）。
- 启用表：settings 新增 section `Cell`，键 `disabled=<id,id,...>`（缺省全部启用；安装即生效符合直觉）。settings 读写走现有 section 机制（common/settings.cpp），旧版本读到未知 section 自动忽略 = 天然向后兼容。

### 3.3 引擎侧模型与排序接入

- 新增成员（pinyin.cpp 类内）：`struct CellPack { std::string id, name; int weight; ... }`；词条并入 `_entries` 尾部（rank 段 = `baseCount + packOffset + i`），**每包一段连续 rank**。
- 排序接入：同键候选按 rank 升序（L831-L845 现有逻辑零改动）→ 包间相对位置由"段起点"决定；第一期段起点按包 id 字典序固定；权重调节（第二期）= 段起点平移。
- 用户词条仍走 count 降序前置合并（L499-L505），细胞词条**不进 userdict.txt、不参与 count 学习**——学习只认用户自己的键。

### 3.4 搜狗 .scel 解析：可行性结论（外部知识，未实测）

.scel 是搜狗私有二进制：GBK 编码，结构 ≈ 文件头 + 词库名 + 词条索引表 + 数据区 + 音节表，社区有成熟逆推（scel2txt 系、rime 导入工具等），存在两代格式（旧/新头标记不同）。**但**：无官方文档、变体多、需真实样本语料验证，且解析结果仍需映射到"音节→全拼键"（.scel 存的是音节 id，需音节表还原）。
**建议：产品内不实现 .scel 加载器；做一个一次性离线转换工具 `tools/scel2cell`（Python 或 C++ 控制台，2~4 人日），把 .scel 转成 .lxcell。** 理由：转换工具出错不影响产品主链路，可人工核对产物；原生加载器出错直接污染候选与内存。若用户拍板"必须要原生 .scel 导入"，按高风险裁决项对待。

### 3.5 与"20000 封顶 + 淘汰"的配额关系（核心决策点）

- **策略一（推荐）：独立配额。** 细胞词条不占用户词典 20000 键额度、不进淘汰池（淘汰只扫 `_userDict`，L1320-L1367 逻辑零改动）。细胞包自身限额：单包 ≤ 200,000 行、启用包合计 ≤ 500,000 行（见 §6 预算）。理由：细胞词库是"静态资产"，用户词典是"学习资产"，两者生命周期与淘汰语义完全不同，混池会让"停用包"无法干净回退。
- **策略二（不推荐）：共享配额 + 优先级。** 细胞词条以 manual 身份并入用户词典（复用 MergeUserDict 通道）。优点：零新代码；缺点：停用包时无法区分"导入的细胞词"与"用户真手动词"（MergeUserDict 现无来源列，L1654），要么加第 5 列破坏现有兼容策略，要么永远无法干净卸载——**等于把"导入不可撤"的现有缺陷放大**。

## 4. 原子性与断电安全

- 导入 = 三段式：① 解析到内存临时 vector（原包文件未动）→ ② 校验全通过（魔数/必填头/音节表/限额）→ ③ `WriteFileAtomicA` 同款 tmp+rename 落 `%APPDATA%\LingxiIme\cell\`。①② 失败：删除半成品 tmp，原库与既有包**零字节变化**，UI 报"第 N 行：原因"。
- 覆盖升级同包（同 id 重装）：先 rename-aside 旧文件（PITFALLS #89：被锁文件用 rename-aside，pinyin.cpp L1373-L1375 已引），再写新件；失败回滚 = 把 aside 件改回。
- 启用/停用：只改 settings 字符串（settings 自身已有原子写机制），引擎侧 `ReloadUserDict` 同款"先 Flush 再重建"（L1501-L1503）。
- 回滚路径：删除 `<id>.lxcell` + 从 disabled 表剔除 id + 触发引擎重建 = 完全卸载；用户词典全程不受影响。
- **"成功"必须独立复核**（卸载脚本 9e3f5dc 教训）：导入完成后 UI 重读落盘文件头与行数，与内存计数比对一致才报成功——不一致报"导入未确认"，禁止只看写盘返回值。

## 5. 失败与降级（不许静默丢弃）

| 场景 | 行为 |
|---|---|
| 魔数/版本不符 | 整包拒绝，报"格式版本不支持（读到 X，支持 1）" |
| 单行词条非法（音节不在表/列数错） | 跳过该行并计数；导入完成报"成功 N 条，跳过 M 条（前 5 条行号）"；跳过率 >10% 视为整包非法拒绝 |
| 文件损坏/非 UTF-8 | 解码失败即整包拒绝（不做逐字节容错——与 LoadUserDict 的"静默跳过"策略**不同**，词库包是外来文件，必须严） |
| 超单包限额（200k 行）/ 超合计限额（500k 行） | 拒绝并报当前合计与差额；提示先停用其他包 |
| 同名 id 已存在 | 询问覆盖/取消；覆盖走 §4 rename-aside |
| 包文件在磁盘被外部删除 | 引擎加载时对缺失包文件跳过 + 写一条 `%APPDATA%\LingxiIme\cell\README` 说明（不弹窗骚扰）；UI 词库列表显示"文件缺失"态 |
| 升级重装覆盖 `exe\data` | 基础词库不受本功能影响；细胞包全在 APPDATA，天然避开 |

## 6. 性能与内存预算（10 万条导入）

- 实测基线：现有引擎启动即解析 300,320 行 / 6.4 MB（§1），10 万条 ≈ 其 1/3，**规模在已验证包络内**。
- 文本量：10 万条 ≈ 2.1 MB（按 6.4MB/300k 线性折算）。
- 解析+建索引：与启动 Load 同量级（现有启动已承受 30 万行；预估单次 ≤300ms 级，**此为推断，需 bench 实测**）。
- 内存增量：`PyEntry` 本体 ≈ 32B(wstring)+24B(vector)+rank + 词面堆 ≈ 80~120B/条；10 万条含五套索引 ≈ **+15~25 MB**。UI 进程本就常驻加载 30 万条，可接受；超限策略见 §5。
- 导入执行线程：第一期放 UI 进程主线程（导入是低频显式操作，2.1MB 解析可容忍短卡顿）；若 bench 超 1s 再移后台 + 进度条（裁决点）。

## 7. 测试设计

**engine_test（台架，可全自动化）**
1. 格式解析：头缺失/id 非法/weight 越界 clamp/BOM/CRLF/空行 → 各报对应错误码，非静默。
2. 边界值：0 条包、1 条包、恰好 200,000 条、200,001 条拒绝；合计 500,000 边界。
3. 排序钉死：同键下"基础词 rank 段 vs 细胞段"顺序符合 §3.3；用户词条仍前置（L499-L505 回归）。
4. 配额隔离：导入 10 万细胞词条后写满用户词典触发淘汰，断言细胞词条**不在**淘汰池、`_userDict` 键数封顶行为不变（对照现有 L10 用例 engine_test.cpp:2432-2456）。
5. 原子性：导入中途注入解析失败 → 断言 cell 目录无残留 tmp、既有包逐字节不变；覆盖导入失败 → aside 回滚后旧包可读。
6. 启停：停用后候选立即不含该包词；重启引擎（ReloadUserDict）状态一致。
7. 兼容：旧版无 cell 目录 / disabled 键缺失 → 全默认值，行为与现在逐字一致。

**必须真机（台架覆盖不到）**
- 词库管理窗安装/启停全流程（UI 交互 + 焦点）；
- 大包导入时打字延迟主观测试（候选窗在输入下不卡顿）；
- 升级重装修复后 `exe\data` 与 `%APPDATA%` 数据保留（关联 9e3f5dc 卸载脚本账本）。

## 9. 三段式结论

- **改什么**：新增 `.lxcell` 纯文本词库包格式（APPDATA 存储、独立配额、启用/停用二值）；引擎把包词条并入 rank 体系复用现有排序；词库管理窗新文件承载导入/启停 UI；导入全程 tmp+rename 可回滚；.scel 只做离线转换工具不进产品。
- **风险**：最大风险是排序接入点触碰拼音核心（L499-L505/L831-L845），需靠钉死用例防回潮；.scel 逆推结果不可保证覆盖全部搜狗版本变体。
- **不改的代价**：用户无法扩展领域词库，与搜狗的核心离线差距（基线 §五 L79）持续存在；现有"导入"通道会把外部词条永久混入用户词典且无法整体卸载，缺口随使用加深。

## 11. 裁决 2026-11-03（用户拍板，本节为唯一权威，与上文冲突处以本节为准）

1. **配额**：独立配额——细胞词条不占用户词典 20000 封顶、不进淘汰池（采纳 §3.5 策略一）。
2. **.scel**：不做产品内原生解析；只做离线转换路线（采纳 §3.4）。**补充研判见 `docs/impl-handoff-2026-11-03.md` §4：不建议自研转换工具，走成熟开源工具 + 导入适配层。**
3. **权重**：第一期不做权重滑杆（权重仅存字段）。
4. **限额**：单包 200k 行 / 启用合计 500k 行，按 §5/§6 执行。
5. **导入线程**：**后台 + 进度，不阻塞 UI**（推翻 §6 "第一期放主线程"的简化建议）。实现约束见交接稿：工作线程只解析到临时文件，引擎合并/索引重建/落盘必须回 UI 主线程执行——`_entries`/五套索引无锁保护，仅主线程可动（pinyin.cpp L575-L630 现状）。
