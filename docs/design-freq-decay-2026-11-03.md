- 状态：**设计稿，待拍板**。全部结论基于 2026-11-03 对当前工作区源码的**静态阅读**，未做构建/运行验证；公式与参数为设计值，非实测调优结果。
- 基线：HEAD `917b5a7`（并行会话在改 `ime/service.cpp`、`ui/main.cpp`、`ui/tray.cpp`，引用这三个文件的行号以当前磁盘状态为准）。
- 对标：搜狗拼音"动态调频"（常用词上浮、久不用下沉），离线。

## 1. 现状实测（file:line 均现读复核）

**count 只增不减**
- 学习入口 `Learn()`：选中上屏（MSG_PICKED，[pipeserver.cpp](file:///d:/Visual%20Studio%20Code/Something/LingxiIme/ui/pipeserver.cpp#L320-L329) L320-L329 转发）后对每个读音键 `++it->second.count`（[pinyin.cpp](file:///d:/Visual%20Studio%20Code/Something/LingxiIme/ui/engine/pinyin.cpp#L1480) L1480）；新词插入 count=1（L1494）。**无任何时间戳字段**：userdict.txt 仅 `词\t键\t次数[\t手动]` 四列（L1159-L1193、L1393-L1409）。
- 唯一降 count 通道 = 手动：`NudgeUserWord`（L1607-L1636，下限 1，L1625）与删除词条/清空（L1532-L1583）。基线文档 L78"只有词条手动遗忘、无自动衰减曲线"与代码一致。

**排序与淘汰全部吃原始 count**
- 候选合并：用户词条按 count 降序、同 count 按词长降，前置插入引擎候选（L499-L505）。
- 淘汰：键数 >20000（L628）时按"键内 Σcount 最小"批量淘汰 5%（L629、L1317-L1367），manual 键豁免（L1338-L1342）。Σcount 是原始值 → **早年刷过的高频词永久压制新词**，只能靠淘汰或手动遗忘，这就是要根治的行为缺陷。

**落盘与生命周期（衰减写盘必须搭的车）**
- 写盘全部经 `KickPersist` 去抖快照线程（L1426-L1455）+ `FlushUserDict` 有界墙钟等待（L1513-L1530，PITFALLS #94 注释 L1519-L1522）+ 退出路径 `main.cpp:651` Flush（H3"停机不析构"形态，L644-L648，**不可改**）。
- 原子写 `WriteFileAtomicA`（tmp+`MoveFileEx`，L1369-L1391）。

**"撤销学习"现状：不存在**
- 全库无 Unlearn/回退机制（grep 无命中）。且上屏后文本归宿主应用，IME 观察不到用户随后按退格——**"上屏后立刻删除自动回退词频"在 TSF 架构下不可自动实现**，只能做成显式动作（见 §3.5）。
- 已有近似设施：屏蔽词表 `_blocked`（L649-L652、L1228-L1250）与"定字取字不 NotifyPicked"（composition.cpp L1171-L1173）说明学习/不学习语义已被谨慎处理，可承接。

## 2. 目标行为

**一句话体验**：打了很久没再打的词会慢慢沉底，最近常用的词浮上来；但用户手动加/调过的词永远不受影响；任何时候关掉衰减，排序回到原始词频态，数据无损。

**明确不做**：
- 不做云端同步衰减、不做按上下文个性化调频。
- 不做"上屏后退格自动回退"（架构不可行，§1 已证；改为显式撤销动作）。
- 不做逐日曲线可视化（UI 只在词典窗显示原始次数，不显示衰减值）。
- 第一期不做衰减参数用户可调（参数进 settings 键但不做设置 UI）。

## 3. 设计

### 3.1 模型选型（核心决策点）

**方案一（推荐）：查询时衰减（derive-at-query），原始 count 永不改写。**
```
score(w) = count(w) × 2^(−age_days(w) / H)
age_days = max(0, (now − last_used) / 86400)      // 时钟回拨钳 0
H = 60 天（半衰期，settings 键 Decay.halfLifeDays，缺省 60）
```
- 排序处（L499-L505）与淘汰处（L1320-L1367 的 keyTotal）改用 score；**持久化只存原始 count + last_used**，衰减是纯派生值。
- 优点：**天然可逆**（改 H / 关闭开关即回原始态，无需快照）；无精度损失；无批量重写盘；测试可注入 now 得到确定性读数。
- 代价：每次合并多几次 `exp2`——用户词条每键 ≤8 条（L1483-L1491 封顶），每次按键增量 <1μs 级（推断，需 bench 钉死）；淘汰批扫 20k 键 × 词数，仅在超限时发生，可接受。

**方案二（不推荐）：批量重写 count（会话结束/空闲/启动时对 count 乘衰减因子取整写回）。**
- 触发点候选：UI 进程退出 Flush 前（main.cpp:651 路径）、启动 ReloadUserDict 时、空闲定时器（**现状：UI 消息循环为阻塞 `GetMessageW`，main.cpp:635，无任何空闲定时器**，需新建）。
- 缺点：取整不可逆、每次重写都全量落盘（放大 9e3f5dc 类数据事故面）、测试时间依赖难钉死。若拍板选它，必须附 §3.6 快照方案。

### 3.2 数据模型与文件格式（向后兼容）

- userdict.txt 新增**可选第 5 列** `last_used`（unix 秒；0/缺失=视为 now）。完全复制第 4 列 manual 的兼容先例（L1178-L1183：缺失列取默认，不报错）。
- 读侧：3/4/5 列老文件照读；写侧：仅当任一条目有非缺省 last_used 时写第 5 列（避免无意义膨胀，同 manual 列"仅手动才写"哲学 L616-L617）。
- `UserPick` 结构加 `int64_t lastUsed`（L613 处）；`Learn()` 顺带刷新 `lastUsed=now`（L1480 旁，零额外 I/O——搭 KickPersist 去抖便车）。
- 旧版本软件读新文件：SplitTsvLine 只取前几列，第 5 列被忽略 = 降级为"无衰减"，可接受（需在文档标注）。

### 3.3 触发时机（按方案一）

- 排序：每次候选合并即时算 score（读内存字段，无锁外开销；`_udMtx` 内，L653）。
- 淘汰：`EvictUserDictKeysLocked` 的 keyTotal 改 Σscore（L1322-L1344 局部改动）→ 语义变为"淘汰最久不用的键"，与衰减目标一致。
- 写盘：**不新增任何触发点**——last_used 更新只搭现有 KickPersist/Flush 路径（L1426-L1455、L1513-L1530），H3 停机不析构形态零触碰。

### 3.4 与 manual 豁免的共存

- manual 词条（第 4 列=1）**同时豁免衰减与淘汰**（衰减 score=count，L1338-L1342 豁免逻辑扩到 score 计算处）：用户显式说"我要这个词"，时间不得否决——与现有"手动永不淘汰"哲学一致。
- 非 manual 词条正常衰减；衰减不改变原始 count，故词典窗显示、`NudgeUserWord`、`AddUserWord(gain)` 语义全部不变（L1585-L1636）。

### 3.5 与"撤销学习"的共存（显式动作，非自动）

- 设计：候选窗高亮项按 **Ctrl+Delete**（或右键"该词在此键不再上屏置顶"）→ 新协议消息 `MSG_UNLEARN`（proto.h 追加 MsgType，旧 DLL/UI 互不认识新消息时按现有"未知消息忽略"处理，需先核实现有未知消息分支）。
- 引擎侧动作：对 (word,key) `count−1`（下限：减到 0 则删条目）并把 `lastUsed` 回退为学习前值——需要 pipeserver 的 `lastLearn`（L604-L612 已存 word/raw/pinned）扩展记录 prevCount/prevLastUsed，窗口 = 该次上屏后、下一次 MSG_PICKED 前。
- 与衰减正交：撤销改的是原始 count 与 last_used，score 自动跟随；manual 词条不可被撤销（撤销只对自学习生效）。

### 3.6 可逆性与快照

- 方案一本身可逆（见 3.1）。额外保险：衰减总开关 `Decay.enabled`（settings，缺省 1）；关闭后排序/淘汰回到原始 count，文件不动。
- 若选方案二才需要快照：`userdict.prev.txt` 单代（写盘前 rename-aside，PITFALLS #89），存储代价 ≈ 现 userdict.txt 大小（实测 11 KB / 716 条，20000 条封顶下 ≤300 KB，可忽略）。

## 4. 原子性与断电安全

- 写盘路径不变（tmp+rename L1369-L1391、去抖线程 L1426-L1455），**不新增文件、不新增线程**——这是对 H3 已定形态最友好的方案。
- 列扩展的迁移安全：读到 5 列而程序只认 4 列 → 忽略；写到 5 列中途断电 → tmp 未 rename，原文件完整（现有机制保证）。
- 回滚路径：关闭 `Decay.enabled` 即回退行为；删除第 5 列（重新导出/导入）即回退数据。

## 5. 失败与降级

| 场景 | 行为 |
|---|---|
| last_used 非法（非数字/负） | 视为缺失（=now），条目不丢；不弹窗（用户词典是自家文件，宽容读，同 L1176/L1184 哲学） |
| 系统时钟回拨 / last_used 在未来 | age 钳 0（score=count），不产生"衰减为 0"误杀 |
| last_used 极旧（>10 年） | score→0 但不为 0（2^-x 渐近）；淘汰仍由 5% 批量机制兜底（L1320），不单独"衰减即删" |
| H 配置非法（0/负/超大） | 读 settings 时 clamp 到 [7, 365]，非法值回缺省 60（对齐 candidateCount 1..9 clamp 先例 settings.cpp:187） |
| 衰减后全键 score 相同 | 排序退化到既有次级键（词长降 L501-L503 → 再退化 rank），必须稳定可测，禁止随机序 |

## 6. 测试设计

**engine_test（可全自动化；关键：注入 now，禁止真实墙钟参与断言）**
1. 公式边界：age=0 → score=count；age=H → 0.5×count；age=2H → 0.25×count；时钟回拨 → age=0。
2. 排序：两条同 count 词条，last_used 差 3 个半衰期 → 新者必须在前；manual 词条不参与衰减（钉死豁免）。
3. 淘汰×衰减：构造"高 count 但极旧"键 vs"低 count 但昨天"键，超 20000 时前者先被淘汰（对照现有 L10 用例 engine_test.cpp:2432-2456 的键数边界 20000/20001 全保留）。
4. 兼容：3 列/4 列老文件读入后行为与现在**逐字节一致**（缺省 now → age=0 → 不衰减 → 现有全部 count 排序用例零回归——这是回归基线本身）。
5. 撤销学习：Learn→UNLEARN→count 回退且 lastUsed 回退；count=1 时撤销=删条目；manual 词条撤销无效（返回 false）。
6. 开关：Decay.enabled=0 → 排序/淘汰回到原始 count。
7. clamp：halfLifeDays=0/-5/10000 → 落回合法域。

**必须真机**
- 长时间跨会话效果（重启后 last_used 生效、衰减主观排序）；
- 候选窗 Ctrl+Delete 交互（焦点/时序，台架不可靠）；
- 真机 e2e 前注意 PITFALLS #92 双实例假红。

## 8. 三段式结论

- **改什么**：userdict.txt 加可选第 5 列 last_used；排序/淘汰改用查询时派生 score（半衰期 60 天，settings 可调可关）；manual 词条豁免衰减；新增显式"撤销学习"（Ctrl+Delete → MSG_UNLEARN）；不新增文件、线程、定时器，写盘全搭现有去抖路径。
- **风险**：排序基准从"原始 count"变为"派生 score"，所有依赖 count 排序的既有用例需确认在"缺省 now → 零衰减"下逐条不变（设计上已保证，需跑全量回归钉死）；撤销学习触碰协议层，旧 DLL+新 UI 混装窗口需按 MsgCtxV1 兼容先例（proto.h L89-L96）处理。
- **不改的代价**：用户早年高频错选词永久置顶（只能手动遗忘或等 5% 淘汰），与搜狗"越用越准"的核心体验差距持续存在（基线 §五 L78）；词库越老越"僵"，自学习价值随时间衰减。

## 10. 裁决 2026-11-03（用户拍板，本节为唯一权威，与上文冲突处以本节为准）

1. **模型**：查询时衰减（方案一）。userdict.txt 加可选第 5 列 `last_used`；score = count × 2^(−age/H)，H=60 天，**实现为可配置常量**（settings 键 `Decay.halfLifeDays`，缺省 60，clamp [7,365]）。原始 count 永不改写。
2. **manual 词条**：**完全豁免**衰减与淘汰（score=count 直通）。
3. **淘汰**：keyTotal 改用 Σscore，与排序同源（EvictUserDictKeysLocked 与候选合并共用同一 score 函数，禁止两套口径）。
4. **撤销学习**：**不进第一期**；第二期做 `Ctrl+Delete` 显式撤销（MSG_UNLEARN 协议届时另立设计）。
5. §3.5 关于"上屏后退格在 TSF 架构下不可自动实现"的复核结论**用户已采纳**，并已据此纠正另一路任务；第一期不实现任何自动回退。

⚠️ 第 5 列的序列化规则有一个连带后果（详见交接稿 §2"会塌的断言"）：Learn 会写 last_used → 落盘行可能从 3/4 列变 5 列（第 4 列需补占位 `0`），engine_test 中**按精确行文本断言 userdict 内容**的既有用例需要实现方按新格式修订断言——修订只允许"扩展列解析"，禁止放宽淘汰/排序行为断言（项目硬约束）。执行顺序与门禁见 `docs/impl-handoff-2026-11-03.md`。
